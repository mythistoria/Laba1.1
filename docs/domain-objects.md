# IDomainObject, композиция и два сценария DAL

Изменения выполнены в ветке `arsenii` на основе коммита `12054cf` с меню выбора EF Core / Dapper. Исходники `View` и `WinFormsApp1` не изменены. Предыдущие исправления ветки `Viacheslav` сюда не переносятся.

## Соответствие заданию

| Пункт | Реализация |
|---|---|
| Второй доменный класс, композиция 1:m | `Student.Grades` содержит `StudentGrade`; каждая оценка имеет обязательного владельца `StudentID`. Удаление студента каскадно удаляет оценки. |
| `IDomainObject` | Интерфейс в `Model` со свойством `int ID { get; set; }`. Оба класса его реализуют. |
| `IRepository` и CRUD | Общий интерфейс в DAL: `Add`, `Delete`, `GetAll`, `GetById`, `Save`. `Add` вставляет, `Save` обновляет. |
| NuGet | Используются уже подключённые `Microsoft.EntityFrameworkCore.SqlServer` и `Dapper`. |
| DLL `DataAccessLayer` | Существующий библиотечный проект сохраняется. |
| EF-сценарий | `Context : DbContext` и `EntityRepository : IRepository`. |
| Dapper-сценарий | `DapperRepository : IRepository`, параметризованные SQL-запросы. |
| Выбор в BL | Поле `IRepository repository`; конструктор выбирает `EntityRepository` или `DapperRepository` по прежнему `StorageMode`. |
| View без изменений | Существующие методы BL и трёхэлементный формат строк для интерфейсов сохранены. Консольное меню последнего коммита осталось прежним. |

`IDomainObject` гарантирует наличие свойства, но не уникальность или положительное значение ID. ID присваивает SQL Server при вставке. Перед вставкой ID должен быть 0, перед обновлением — положительным.

## Контракт репозитория

```csharp
int Add(IDomainObject item);
bool Delete<T>(int id) where T : class, IDomainObject;
List<T> GetAll<T>() where T : class, IDomainObject;
T? GetById<T>(int id) where T : class, IDomainObject;
void Save(IDomainObject item);
```

`Add` и `Save` принимают оба доменных класса через общий интерфейс. Для чтения и удаления указывается тип: ID студента и ID оценки могут совпадать, поскольку относятся к разным таблицам.

Обе реализации поддерживают `Student` и `StudentGrade`. Иной доменный тип, который не описан в модели БД, отклоняется. `GetAll` сортирует результат по ID, `GetById` возвращает `null`, если запись отсутствует, `Delete` возвращает факт удаления. `Save` не создаёт отсутствующую запись.

## Композиция и сохранение

- EF явно настраивает обязательный FK `StudentGrade.StudentID` и `DeleteBehavior.Cascade`.
- В SQL тот же FK имеет `ON DELETE CASCADE`, поэтому поведение одинаково для EF и Dapper.
- При чтении студента загружаются его оценки. При чтении оценки также восстанавливается её владелец с полной коллекцией оценок.
- `Save(student)` обновляет поля, добавляет новые оценки, изменяет существующие и удаляет исключённые из коллекции. В EF используется один `SaveChanges`, в Dapper — одна явная транзакция.
- Нельзя сохранить студенту чужую оценку или перенести существующую оценку другому владельцу. Это проверяется перед сохранением и обеспечивается условиями SQL-запросов.
- Добавление оценки существующему студенту не вставляет самого студента повторно.

Пример использования DAL, без изменения пользовательского интерфейса:

```csharp
IRepository repository = new EntityRepository(); // либо new DapperRepository()
var student = new Student
{
    Name = "Иван Иванов",
    Speciality = "Программирование",
    Group = "ПИ-21",
    Grades = new List<StudentGrade>
    {
        new() { Subject = "Математика", Value = 4 },
        new() { Subject = "Программирование", Value = 5 }
    }
};
repository.Add(student); // ID студента и его оценок присваивает база
var saved = repository.GetById<Student>(student.ID)!;
saved.Grades.First().Value = 5;
repository.Save(saved);
```

## Существующая база

Свойство `Student.ID` отображается на прежнюю колонку `Students.Id`, поэтому переименовывать её и менять существующие идентификаторы не нужно. При запуске `DbInitializer` создаёт отсутствующую таблицу `StudentGrades` и её внешний ключ, сохраняя таблицу студентов. Для новой пустой базы тестовое заполнение включает две оценки у первого студента; существующим студентам оценки автоматически не добавляются.
