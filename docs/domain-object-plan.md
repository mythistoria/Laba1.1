# Адаптация лабораторной под IDomainObject

Основание: ветка arsenii, коммит 12054cf. Выбранные пользователем классы: Student и StudentGrade.

## Требования

- Model.IDomainObject задаёт int ID { get; set; }; оба доменных класса его реализуют.
- Student содержит коллекцию Grades. StudentGrade имеет обязательную ссылку на одного Student; внешний ключ и каскадное удаление обеспечивают композицию 1:m в БД.
- Общий негeneric IRepository задаёт Add, Delete, GetAll, GetById, Save. Add и Save принимают IDomainObject; методы чтения и удаления обобщены с ограничением class, IDomainObject, чтобы явно выбирать доменный тип и его таблицу.
- Context : DbContext, EntityRepository : IRepository и DapperRepository : IRepository находятся в существующей DLL DataAccessLayer. Уже подключённые EF Core и Dapper сохраняются.
- Add вставляет новый объект и присваивает выданный БД ID; Save обновляет существующий объект. Сохранение Student синхронизирует его оценки одной транзакцией; удаление Student удаляет его оценки.
- BusinessLogic хранит IRepository и выбирает реализацию по прежнему StorageMode. Существующие методы BL, форматы результатов и исходники обоих интерфейсов сохраняются.
- Для прежней базы с колонкой Students.Id свойство ID отображается на эту колонку. Отсутствующая StudentGrades создаётся без удаления прежних студентов.
- Тестовый проект не добавляется по решению пользователя. Проверки: сборка, метаданные EF, неизменность View и WinForms. Нативная проверка SQL Server LocalDB требует Windows.

## Последовательность

1. Добавить IDomainObject и StudentGrade; обновить Student.
2. Обновить IRepository и Context, явно настроить 1:m и каскад.
3. Реализовать CRUD обоих репозиториев для двух классов, включая сохранение состава оценок и проверку принадлежности оценки студенту.
4. Перевести только внутренние обращения BL и инициализатор на новые имена/API.
5. Собрать решение, проверить метаданные модели и неизменность интерфейсов, провести ревью.
